Libraries

Where sources set to "Movies" publish. Only libraries that can hold movies are listed — a movies library, or a mixed one.
Where sources set to "Series" publish. Pick the same library as above to keep everything together — a library that can hold both is a mixed one. Each library must exist, but needs no scan: a small .keep file is written into its folder, because Jellyfin skips a library folder that holds no files at all.
Applies to a mixed library only, so sorting by date added follows publication order. It has no effect on a movies-only or series-only library, where the view is already right. Note the trade-off: a channel you add today but which has been running for years will never appear in "Recently added", because its videos keep their old release dates. You can turn this back off at any time — nothing is overwritten. Re-typing a mixed library has the same effect as turning it off.
Base URL used to build stream URLs. Must be reachable by the Jellyfin server itself (loopback is fine for single-host setups).

Playback

How long filtered HLS master playlists are cached before being re-fetched.
How often sources are polled for a broadcast in progress. Set to 0 to disable. A listing alone cannot find a live in time: it runs per source every 720 minutes by default. The task itself wakes every 5 minutes, so any value below 5 behaves as 5.
How fast background work may call yt-dlp for one platform — listings, metadata waves and the live probe share this budget, and two platforms advance independently. A started video is never held back by it. Raising it risks the platform rate-limiting the whole session for up to an hour.
How many videos one wave fetches before the library is updated. Each video costs one yt-dlp call, paced by the rate-limit setting above; this is the granularity at which new videos appear — a smaller value publishes more often, a larger one covers more ground per turn.
Initial delay before a failed video is retried. The delay doubles on each consecutive failure and is capped unconditionally at seven days. A failure the platform caused — a rate limit, a timeout — does not count towards it.
Each source is listed often (see its own interval below), but that short listing only sees the head of the list. Only a full one notices that a video was DELETED, or renamed further down — so this is how long a removal can take to reach the library. A full listing costs one request per 30 videos.
Spreads the listing work instead of spending every source's budget at once. The most overdue sources go first, so a low value delays nothing indefinitely — the turn is just shorter and the task comes round again.
How long a video's title, synopsis and quality list may go unrefreshed. This is also what retries a video the platform called unavailable: there is no separate rule for those any more.
A language code such as fr or de, pinned when a source is listed. YouTube serves translated titles there when a channel provides them. Leave it empty to publish whatever each channel calls its original title — which is a valid choice, not a missing setting.
Comma-separated BCP-47 language prefixes (e.g. en, fr). Matching audio renditions are kept in HLS masters, original track always included. Leave empty to keep the original track only.
Comma-separated BCP-47 language prefixes (e.g. en, fr). Matching subtitle tracks are included in HLS masters. Leave empty to include no subtitles.
